# scene3d/dressing (W)

## drone.glb

- **Licence: CC0 1.0.** Our own procedural model, generated by `tools/scan_make_drone.py`
  (re-run it to change anything). No third-party assets.
- 68 kB, ~3.9k triangles, no textures.
- **Axes (glTF standard):** +Y up, **+X forward**, origin at the body centre.
  Span 0.50 m prop tip to prop tip (= sim `DRONE_RADIUS` 0.25 m), ~0.13 m tall.
- Forward cues: camera gimbal + white nav lights at the front, red nav light at the back,
  `accent` arrow on top pointing forward.
- **Nodes:** `prop_FL`, `prop_FR`, `prop_RL`, `prop_RR` (each centred on its own origin;
  spin about local +Y), plus `body`, `arms`, `motors`, `skids`, `camera`, `lens`,
  `accent`, `nav_front`, `nav_rear`.
- **Materials:** `accent` (white base, LED ring + top arrow): tint it per drone.
  `prop` is 45 % transparent. `nav_front` / `nav_rear` are emissive.

### Using it inside `<SimFrame>` (z up, `rotation.z = yaw`, +x forward)

The model is y-up, so wrap it once in a +90° X rotation; the existing outer group's
`rotation.z = d.yaw` then turns it, and +X stays forward.

```tsx
import droneUrl from './dressing/drone.glb?url'
import { useGLTF } from '@react-three/drei'
import { SkeletonUtils } from 'three-stdlib'

function DroneModel({ colour }: { colour: string }) {
  const { scene } = useGLTF(droneUrl)
  const model = useMemo(() => {
    const m = SkeletonUtils.clone(scene)          // one copy per drone
    m.traverse((o: any) => {
      if (o.isMesh && o.material?.name === 'accent') {
        o.material = o.material.clone()
        o.material.color.set(colour)
        o.material.emissive.set(colour)
      }
    })
    return m
  }, [scene, colour])
  useFrame((_, dt) => {                          // spin the props
    for (const [n, dir] of [['prop_FL', 1], ['prop_RR', 1], ['prop_FR', -1], ['prop_RL', -1]] as const)
      model.getObjectByName(n)!.rotation.y += dir * 60 * dt
  })
  return <group rotation={[Math.PI / 2, 0, 0]}><primitive object={model} /></group>
}
```

Lost drone: the model already falls with the group (`z = 0.25`); stop the props and set
the `accent` / `nav_*` emissive to black.

## Disaster dressing: `<Dressing />`

Fog, smoke DIFFUSION (a concentration field over grid.png's floor: diffuses cell to cell, walls block it, fires are sources, a thin dark-brown haze everywhere), red emergency beacons, floating dust; fire (flames, smoke that rises and spreads
under the ceiling, embers, flickering light, scorch); rubble piles in brown shades (faceted fractured chunks, jagged slabs, leaning beam,
rebar, gravel spill, contact shadow, baked light/AO/dirt mottling). All procedural: no files, works offline, CC0.

**Mount (D, one line inside `<SimFrame>` in `Scene3D.tsx`):**

```tsx
import { Dressing } from './dressing'
// ...
<SimFrame>
  ...
  <Drones />
  <Dressing />
</SimFrame>
```

- **What it shows (default `reveal="belief"`):** only what the swarm has found. Belief
  `fire` cells become fires (this includes the flare-up), and `blocked_new` cells become
  rubble (about one pile per metre of detected debris face). Judge clicks
  (`state.click_handles`) are dressed straight away. It never reads hidden scenario
  fields, so the dashboard rule on `/api/maps/{name}/scenario` holds.
- `reveal="world"` shows the scenario's real fires and debris from the start, using that
  editor-only endpoint. Only use it where the team agrees, e.g. the firefighter view.
- **Your click objects:** keep or drop your cones and boxes. `RubblePile` and `FireFX` are
  exported if you'd rather render clicks yourself.
- **Switches:** `?dressing=off` and `?dressing=lite` (no smoke or dust, thinner fog).
- **Cost:** not measurable on an M4 Pro at 1080p (700–800 FPS with or without it).
  Lights: 4 beacons plus 1 per fire.
- **Works with the unlit scan + 2.3 m dollhouse cut (#33).** Lights don't reach the unlit scan,
  so firelight and the emergency red are faked with tinted floor pools and halos that
  flicker or pulse with them. Rubble is unlit too, with baked shading. Smoke spreads and the
  beacons hang below 2.3 m. The fog is smoky grey-brown, thick at drone height and thin from
  the overview camera.
- **Preview without the sim:** `npm run dev` + `uv run python -m sgr.server.dev --map maps/<name>`, then
  open `/src/scene3d/dressing/preview.html?map=<name>&view=overview|fire|rubble|corridor|hall`.

## People: `firefighter.glb`, `survivor.glb` + `<FirefighterFigure>`, `<SurvivorFigure>`

Realistic but cheap, for the 3D view only. Procedural low-poly figures from
`tools/scan_make_people.py` (CC0, our own): adult proportions (1.78 m), no textures, no
skeleton, parts merged per colour.

| | triangles | draw calls | size |
|---|---|---|---|
| firefighter (navy turnout gear + hi-vis bands, yellow helmet, mask, air cylinder) | 7.5k | 9 | 144 kB |
| survivor (lying on the back, hi-vis yellow-green jacket, jeans) | 4.6k | 5 | 88 kB |

Each has a soft contact shadow; the survivor breathes slightly, and the firefighter bobs when
`moving`. Axes are glTF y-up with +X forward; the components already convert to the sim frame.

**Swap-in (D, in `Scene3D.tsx`, inside `<SimFrame>`; wrap in `<Suspense>`):**
```tsx
import { FirefighterFigure, SurvivorFigure } from './dressing'
// SurvivorMarker: same props as SimSurvivor
<SurvivorFigure x={s.x} y={s.y} opacity={s.status === 'confirmed' ? 1 : 0.6} />
// Act 2 firefighter (state.ff = {x, y, yaw}); moving = speed > ~0.2 m/s
{ff && <FirefighterFigure x={ff.x} y={ff.y} yaw={ff.yaw} moving={moving} />}
```
The drone cameras (MuJoCo, P) keep their simple shapes: the detector is tuned on them.
